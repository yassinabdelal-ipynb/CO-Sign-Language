# Results and reproduction

## Newly executed checks

On Windows 11, NVIDIA GeForce RTX 5060 Laptop GPU, 8,151 MiB VRAM, driver 610.60, Python 3.14.7, PyTorch 2.14.1+cu130, NumPy 2.4.6, Pillow 13.0.0:

- **16/16 CPU tests passed** after the final source changes. No camera, evaluation dataset or trained eye-state checkpoint was used by the unit tests.
- Event replay emitted all **29 expected commands** from the explicitly generated fixture.
- The supplied best-epoch checkpoint loaded strictly into the **1,879,878-parameter** model; output was finite and six-dimensional.
- CPU/CUDA output probabilities agreed within **1.79e-07** on one generated input, using atol=0.0001, rtol=0.001. This is numerical compatibility, not recognition accuracy.

## Bounded measurement of the supplied checkpoint

Final run: seed 2025, one 350×150 generated grayscale input, float32 model input 1×1×224×224, 2 warmups of each timing scope, 10 recorded repetitions per scope. No failed samples. Checkpoint SHA-256: `330c19c2711a5c711624c183b968cae0923427395ffe8d24bd494b4525b278a7`.

| Scope | Median | Min–max | Sample standard deviation |
| --- | --- | --- | --- |
| Request: grayscale/resize + host/device transfer + inference + returned probabilities | 7.61 ms | 7.43–8.40 ms | 0.35 ms |
| Device execution: CUDA events around model forward on prepared input | 7.19 ms | 7.10–9.93 ms | 0.88 ms |

Model setup was measured separately: 160.11 ms. Peak allocated PyTorch GPU memory was 48.32 MiB; this is not reserved memory or whole-process GPU usage. Camera capture, face/landmark detection, eye-state filtering and rendering are excluded. Laptop clocks, power mode and other activity were uncontrolled. Do not convert model-only timing into a claim of sustained webcam FPS.

All actual measurement attempts are retained:

- `checkpoint-initial-scope.json`: first attempt warmed the model-only path but not the full request path. Its first request took 59.57 ms. This scope gap prompted a warmup correction; the first sample is not silently removed.
- `checkpoint-verification.json`: corrected warmup for both scopes; request median 8.44 ms, range 8.11–8.96 ms.
- `checkpoint-verification-final.json`: final source verification, summarized above. Source hashes, exact versions, raw samples and UTC timestamp are in the file. Different run medians illustrate laptop variability; they do not establish a speedup.

The stable core was tested using existing PyTorch and plotting environments together through a process-local Python import path; no packages in those environments were modified. Their exact versions are recorded above. This was not a fresh installation of the pinned Python 3.10–3.12 collection stack. Earlier inspection found an existing Python 3.10.20 training environment with torch 2.12.0.dev20260315+cu130, NumPy 1.26.4, Pillow 12.1.1, MediaPipe 0.10.21, OpenCV contrib 4.11.0.86, dlib 20.0.1 and TensorFlow 2.19.0; it was not updated.


The scripts were invoked with the installed interpreters described above, not an activated global environment. Local checkpoint paths are omitted from publication. `nvidia-smi` verified actual GPU/VRAM/driver. `scripts/doctor.py` reports whether compiler tools are on PATH; no compiler is required for the core.

After a clean local setup, reproduce the checkpoint check with:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\benchmark.ps1 -Checkpoint 'weights\comeback_best.pt' -Device cuda
```

It writes new results to private `local/`; it does not overwrite supplied evidence. For CPU inference, choose `-Device cpu`.
